EDID 速成课

从 128 字节的二进制结构，到上面这些工具到底在算什么。

1 · EDID 是什么

EDID（Extended Display Identification Data，扩展显示标识数据）是显示器向主机介绍自己的一张“电子名片”。显卡通过 DDC/I²C 通道在显示器上电时读取它，据此决定默认分辨率、色深、色彩空间、是否支持音频等。

数据以 128 字节为一个基本单位，称为一个 block（块）。第 1 块（基础块，Base Block）承载厂商、产品、色度和基础时序；后续扩展块描述更多能力。

  • 规范由 VESA 维护，常见版本 EDID 1.3（2006 年前后为主）与 EDID 1.4（现行）。
  • 每块第 127 字节（偏移 0x7F）是 校验和：使整块 128 字节累加后低 8 位为 0。
  • 基础块偏移 0x7E 记录 扩展块数量，因此整份 EDID 长度必为 128 × (1 + N)。

3 · 四种描述符

偏移 0x36 起有 4 个 18 字节槽位，每个槽位要么是 详细时序描述符（DTD），要么是“显示器描述符”。区分方式：前两字节为 00 00 且第 2、4 字节也为 0 时，是显示器描述符，标签在第 3 字节。

常见标签：0xFC 显示器名称 · 0xFF 序列号 · 0xFE 自由文本 · 0xFD 行频场频范围 · 0xFB 附加白点 · 0xFA 附加标准时序 · 0x10 空描述符。

文本类描述符的 13 个字符必须以 0x0A 结尾、其余用 0x20 补齐；因此名称最多 12 个字符。

第 1 个槽位若为 DTD，就是“首选时序”——显示器原生分辨率，主机默认优先使用。

4 · 详细时序描述符（18 字节）

字节含义
0–1像素时钟（10 kHz 为单位，小端）
2–4行有效像素、行消隐、二者高 4 位
5–7场有效行数、场消隐、二者高 4 位
8–9行同步偏移（前肩）、行同步宽度
10–11场同步偏移 / 宽度，以及各字段高位
12–14图像横向 / 纵向尺寸（mm）及其高位
15–16上下左右边框像素
17隔行、立体、同步类型与极性

刷新率 = 像素时钟 ÷ (行总数 × 场总数)；行总数 = 有效 + 消隐。

5 · 扩展块：CEA-861 与 DisplayID

CEA-861（标签 0x02）是电视 / HDMI 显示器的重头戏：用“数据块集合”描述支持的分辨率、音频、扬声器布局与厂商能力。

  • 视频数据块：一字节一个 VIC（如 16 = 1080p60、97 = 4K60），最高位置 1 表示原生格式。
  • 音频数据块：每 3 字节描述一种格式（LPCM / AC-3…）、声道数与采样率。
  • 厂商数据块：以 OUI 开头，00 0C 03 即 HDMI 1.4 的 VSDB，内含物理地址与 TMDS 上限。
  • 扩展数据块：第 1 字节是扩展标签，0x06 为 HDR 静态元数据，0x05 为色度（Colorimetry）。

DisplayID（标签 0x70）取代 CEA 用于 DisplayPort，用“分节”结构承载显示参数、色度与更高效的时序编码。

其他扩展：0x10 VTB 时序块、0xAF / 0xF0 块映射表。

6 · CVT 与 GTF：时序是怎么算出来的

已知分辨率与刷新率时，需要推导出消隐、同步宽度等全部参数。VESA 定义了两套公式：

  • GTF（广义时序公式）：较早，用 40 行频段做折中，普遍用于 CRT 时代与旧显示器。
  • CVT（通用时序公式）：为液晶优化，提供 标准消隐 与 缩减消隐（RB / RBv2 / RBv3）；RB 系列把消隐压到很小，显著降低像素时钟，是 144 Hz、4K 以上高刷的必需品。

CVT 的场同步宽度由宽高比决定（4:3 → 4 行，16:9 → 5 行，16:10 → 6 行，5:4 / 15:9 → 7 行，其余 10 行）；像素时钟在 CVT 1.1 下按 0.25 MHz 截断，CVT 1.2（RBv2/v3）则精确到 0.001 MHz。

时序计算器同时输出 X11 Modeline 与 xrandr --newmode，可直接粘贴到 Linux 自定义分辨率。

7 · 常见的“坑”

  • 校验和错一位：整块失效，很多驱动会直接忽略整份 EDID。
  • 扩展块数量与实际不符：主机按声明数量读取，会读到垃圾数据。
  • 首选时序不在第 1 槽位：等于没有原生分辨率，系统可能落到 1024×768。
  • 声明了 sRGB 但色度字节不是 sRGB 值：色彩管理会明显偏色。
  • HDMI / DP 却没有 CEA-861 扩展块：分辨率和音频能力不会被完整识别。
  • 文本描述符没有 0x0A 结尾：名称会带上垃圾字符，或在第 13 字节被截断。

用“校验”标签页逐项排查，错误会精确定位到字节与槽位。

关于本工具

这是一个 完全离线 的 EDID 工具箱，功能覆盖 edidcraft.com 的解析、生成、校验与时序计算四大部分，但所有运算都改由浏览器端 JavaScript 实现：

  • 没有后端、没有 API 请求，断网可用；
  • 不加载任何 CDN 资源（图标为内联 SVG、字体为系统字体）；
  • 直接双击 index.html 即可用 file:// 打开；
  • 因为全部是静态文件，可以直接放到 GitHub Pages / Gitee Pages / 任意静态托管。

你的 EDID 数据始终留在本机内存里，刷新页面即消失（仅在本地保存主题与表单草稿）。

部署到 GitHub Pages

  1. 新建仓库并把 edidcraft-local 内的文件推到根目录（或 docs/）。
  2. 仓库 Settings → Pages，Source 选分支 main 与目录 /(root) 或 /docs。
  3. 等待一分钟，访问 https://用户名.github.io/仓库名/。
  4. 本工具用相对路径引用资源，放在子目录里也能正常工作。

部署到 Gitee Pages

  1. 推送代码到 Gitee 仓库，进入 服务 → Gitee Pages。
  2. 选择分支与部署目录，勾选强制 HTTPS，点击“启动”。
  3. 注意：Gitee Pages 免费版需要手动点击更新，且可能要求实名。
